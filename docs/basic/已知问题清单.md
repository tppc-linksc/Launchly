## 1. 分类和状态

### 1.1 类型

| 类型 | 含义 |
| --- | --- |
| 功能缺陷 | 当前代码的行为与明确合同不一致 |
| 安全缺陷 | 认证、授权、秘密或隔离边界存在可确认风险 |
| 工程阻断 | 构建、启动、迁移或交付链路无法继续 |
| 测试缺口 | 关键行为没有自动化或真实环境证据 |
| 架构缺口 | 当前实现与已确定的目标架构或身份模型不一致 |
| 技术债 | 当前不一定阻断，但会造成性能、维护或扩展问题 |
| 产品死路径 | 界面展示了没有真实行为或后端合同的操作 |

### 1.2 严重度

| 等级 | 规则 |
| --- | --- |
| P0 | 阻止启动/部署，或存在跨租户、秘密、认证等高风险问题 |
| P1 | 核心功能错误、重要合同断裂或明显质量风险 |
| P2 | 不阻断主链路的性能、体验和维护问题 |

### 1.3 状态

| 状态 | 含义 |
| --- | --- |
| 已确认 | 已有源码或可复跑命令证明，尚未开始修复 |
| 处理中 | 对应任务已有获准实施变更 |
| 待验收 | 修复代码存在，但对应 BASE/E2E 尚未通过 |
| 已关闭 | 修复和规定验收均通过 |
| 暂缓 | 问题成立，但当前阶段明确不处理 |

## 3. 修复摘要（本轮 R0-04/05/06/08/11 集中推进）

### 3.1 授权与 DTO（KI-004/005/016/018）

- 新增 `services/api/src/common/access/project-resource-access-policy.ts`：统一 Project/Environment/Variable/DeployTarget/Issue/Release/Test/Deployment 子资源的 Workspace→Project→角色三段校验。
- 新增 `services/api/src/project/dto/component.dto.ts`、`services/api/src/release/dto/exempt-gate.dto.ts`，并补 `UpdateTestCaseDto`。
- `ProjectAccessService.require` 与 `ProjectResourceAccessPolicy.requireProject` 双重 fail closed：未知角色抛 `InternalServerErrorException`，不再静默降级。
- `EnvironmentVariable` 表新增 `@@unique([environmentId, key])` 约束，迁移文件 `20260818000000_environment_variable_unique_key`，Service 层显式拒绝重复 key。

### 3.2 密钥与日志（KI-010/011/028/030/032/035）

- `AuthService` 区分 Access/Refresh Token：`aud`、`typ`、`jti`、撤销集合；`resolveCorsConfig` 强制 wildcard 与 credentials 不同时出现。
- 新增 `services/api/src/worker/runners/secret-redactor.ts`：纯函数 + JSON 感知，支持 Bearer、DSN、PEM、GitHub Token；51 个测试全部通过。
- 新增 `services/api/src/worker/runners/ref-id-safety.ts` 单一权威 ID 校验。
- `RemoteSshRunner` 强制 `sha256:[0-9a-f]{64}` digest、OCI imageRef 白名单、任务专属 `work-${refId}` 子目录与 finally 清理。

### 3.3 Worker 状态机（KI-025/026/027/029）

- `WorkerService` 与新增的 `worker-state-machine.ts`：`isDeploymentStagesComplete` 拒绝空集合；未知 taskType 与非法 payload fail closed；超时任务按 attempts 决定 PENDING/FAILED。
- 自动回滚 stepOrder=6 > HEALTH_CHECK 的 5，避免乱序。

### 3.4 Webhook 与 Git（KI-012/033）

- `WebhookService` 只按 installation_id + repository_id 精确匹配；installation 还必须通过 operator 配置显式绑定 Workspace，缺失或冲突时 fail closed。
- `GitRunner.execute` 指定 commitSha 时 fetch + detached checkout 任一步失败 fail closed，并核对 HEAD 一致性。

### 3.5 Shell 健康检查（KI-038/039）

- `ShellRunner.executeHealthCheck` 改用 `execFile('curl', args)`，host/path 严格白名单，状态码必须 2xx 才算成功。

### 3.6 测试覆盖（KI-006）

- API coverage 合并 45 个单元 suite 与 2 个 HTTP E2E suite，47 suites / 1218 tests 全通过；覆盖率为 86.51%/70.08%/80.59%/87.87%（Statements/Branches/Functions/Lines）。
- Web 30 files / 363 tests 全通过；覆盖率为 96.27%/85.37%/70.43%/96.27%。
- CLI 已拆为职责单一模块，`vitest` 56 个测试全部通过；Compose 拓扑一致性测试覆盖仓库模板与 CLI 模板的服务、卷、隔离网络和 Worker 健康配置。
- 三端均无 skip/only/todo，并已达到[测试补全任务书](./测试补全任务书.md)的 R0 全局数值门槛；KI-006 只保留真实数据库、升级/恢复和部署故障矩阵缺口。

### 3.7 语义化审计事件（外部审核 A-14）

- 全局 mutation interceptor 继续只记录成功写请求，不保存请求体或邀请 token 等字面路径参数。
- 密钥轮换、环境变量增删改、邀请/成员变更、DeployTarget 增删改/验证和 Release 创建/发布/豁免均映射为稳定的领域事件，不再只留下 `HTTP_POST/PUT/PATCH/DELETE`。
- 创建场景优先使用响应资源 ID，其余场景回退到受限长度的路由参数；持久化失败不改变原业务响应，并有 32 条拦截器合同测试及真实 HTTP 路由断言锁定分类、身份、脱敏和失败边界。

## 4. 维护规则

1. 新问题必须包含可复跑命令或源码链接；只有猜测时标记"待复核"，不能写成已确认。
2. 修复开始后只更新状态和关联任务，不在本清单展开实施方案。
3. 修复提交存在但验收未通过时只能标记"待验收"。
4. 关闭时补充 commit、验收 ID 和证据链接；不得删除历史编号。
5. 测试失败暴露的新缺陷先创建 `KI-###`，不能让测试执行者顺手修改业务代码。
