> **版本**：2.2
> **代码基线**：`0172e94`（2026-09-02）三端 R0 覆盖率门禁
> **用途**：把测试补全拆成可独立执行、可严格复核的工作包。已知缺陷见[已知问题清单](./已知问题清单.md)，阶段退出见[交付验收规范](./交付验收规范.md)。
> **重要边界**：本任务书只授权测试和测试基础设施工作，不授权修复业务代码或修改产品行为。工作包状态只代表测试包级验收，不代表 BASE/E2E 或产品问题已关闭。

## 1. “测试要全”的定义

“全”不等于追求一个漂亮的覆盖率数字，而是同时满足：

1. **全量统计**：覆盖率工具必须统计全部生产源码，未被任何测试加载的文件也显示为 0%。
2. **场景完整**：正常、拒绝、边界、并发、重试、清理、跨 Workspace 和秘密不泄露均有测试。
3. **层级完整**：单元测试、模块/数据库集成测试、生产启动烟雾测试和真实 E2E 不能互相替代。
4. **断言有效**：断言最终状态、输出、错误或副作用；不能只断言 Mock 被调用。
5. **失败可解释**：若测试暴露业务缺陷，记录到[已知问题清单](./已知问题清单.md)，不得在测试任务中顺手改生产代码。

覆盖率只是最低门槛，显式场景矩阵必须 100% 完成。

## 4. 执行纪律

每次只委派一个 `TEST-*` 工作包。执行者必须遵守：

### 4.1 允许

- 只修改工作包白名单内的测试、测试配置和明确列出的依赖文件。
- 使用 Jest/Vitest、Nest TestingModule、临时目录、fake timers 和严格 Mock。
- 测试暴露缺陷时提供最小复现，不修改业务代码。

### 4.2 禁止

- 修改 `services/api/src`、`apps/web/src`、`cli/src` 中的生产文件，除非白名单明确列出。
- 删除、跳过、改名隐藏现有测试，使用 `.only`、`.skip`、`todo` 或无断言用例。
- 缩小 `collectCoverageFrom`/coverage include，增加无理由 exclude 或 Istanbul/V8 ignore。
- Mock 被测对象本身，或者仅断言 `toHaveBeenCalled()` 就声称行为正确。
- 访问真实网络、Docker、SSH、用户主目录或长期目录。
- 修改 README、路线图、已知问题状态、验收状态或声称整个项目完成。
- 自动提交、推送、部署或清理不属于测试创建的文件。

### 4.3 必交证据

## 8. 建议委派顺序

一次只发一个任务，按以下顺序：

1. TEST-000：先让覆盖率可测。
2. TEST-API-01：纯函数和安全基础。
3. TEST-API-02：Environment/Variable。
4. TEST-API-03：ProjectAccess/RepositoryHints/Catalog。
5. TEST-API-04：Release/Notification/Test。
6. TEST-API-05：DeployTarget/SSH 隔离单元测试。
7. TEST-API-06：Worker 状态机。
8. TEST-API-07 已按 07A、07B、07C-1、07C-2 分别验收完成。
9. TEST-API-08、TEST-WEB-01/02、TEST-CLI-01C 已完成包级验收；当前不再开放新的低风险委派包，下一阶段必须由 Codex/人工主导真实数据库、迁移、备份和部署 E2E。

不应把 TEST-000 至 TEST-API-07 一次性全部交给同一个执行者，否则无法确认覆盖率增长来自哪一批测试，也难以及时发现越界修改。

## 10. Codex 复核清单

每批 MiniMax 结果由 Codex 独立检查：

1. diff 是否只在白名单内，是否触碰/掩盖用户已有改动。
2. 是否完整阅读了被测文件，测试名和分支是否与实现一致。
3. 是否 Mock 被测对象、只测调用次数、写 tautology 或复制实现逻辑。
4. 是否有 `.skip/.only/todo`、弱断言、大 snapshot、coverage ignore 或统计范围缩小。
5. 是否恢复 env/timer/Mock，清理临时文件，测试可重复运行。
6. 独立运行目标测试、全量测试、coverage、build 和 `git diff --check`。
7. 比较 JSON summary 的分母；分母异常下降视为覆盖率造假或配置错误。
8. 发现生产缺陷时新增/更新 `KI-###`，不得把红测当成测试任务完成。
9. 只有全部证据通过后，才更新 TEST 状态；不自动关闭 R0 或 BASE。
