# Launchly 交付验收规范

> **版本**：1.0
> **生效日期**：2026-07-22
> **地位**：Launchly 功能完成、版本发布与对外“已完成”声明的唯一验收标准。

## 1. 证据等级

| 证据 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 单元/集成测试 | 受测逻辑和接口契约 | Docker、SSH、HTTPS、真实回滚或安全性 |
| 构建/镜像 | 编译与制品可生成 | 服务可启动、迁移或部署成功 |
| Compose 启动 | 特定环境下服务可启动 | Git webhook、节点隔离、故障恢复 |
| 真实 E2E | 给定版本在真实 Git、PostgreSQL、Docker、SSH 目标机和 HTTPS 中完成闭环 | 仅覆盖的场景，不代表全部安全结论 |

没有对应真实 E2E 记录的能力必须标记为“未验收”，不得称为完成、生产可用或自动化部署已实现。

## 2. 每次验收记录的最小内容

验收记录必须可复跑且不泄露秘密，包含：版本/commit、测试日期、执行者、Self-Host/Cloud 形态、Ubuntu/Node/Docker/PostgreSQL 版本、Git 仓库和目标机的非敏感标识、命令/配置摘要、部署 ID/镜像 digest、脱敏日志、预期、实际和清理结果。密码、Token、私钥、完整连接串和环境变量值不得进入记录。

## 3. 发布阻断用例

| ID | 场景 | 通过条件 |
| --- | --- | --- |
| E2E-01 | GitHub Push 自动部署 | push 后无需登录服务器，HMAC 验证、去重、检出、构建、部署、健康和 commit 状态回写均可证明 |
| E2E-02 | 同机并发两项目 | 两个项目同时部署，Compose/network/directory/volume 无冲突，互删/重启不会影响对方 |
| E2E-03 | 域名与 HTTPS | 自动签发并续期路径可验证；节点重启后代理和应用自动恢复 |
| E2E-04 | Worker 故障 | 部署中杀死 Worker，任务依 lease 安全重领或重试，API 持续健康，无重复副作用 |
| E2E-05 | 健康失败自动回滚 | 候选版本健康失败时不切流量，旧版本仍可访问，记录真实 rollback 事件 |
| E2E-06 | 密钥保密 | 环境变量正确注入；Web、API、任务 payload、日志和审计导出均无明文 |
| E2E-07 | 迁移失败 | Release Phase 失败后旧版本与数据可用，流量不切换，失败可追溯 |
| E2E-08 | 外部依赖真联调 | 使用真实 GitHub、Docker Registry、PostgreSQL、SSH 目标机和 HTTPS 完成 E2E-01 至 E2E-07 |
| E2E-09 | 运维恢复 | 验证备份、恢复、升级、回滚、镜像/构建缓存和磁盘清理；恢复后重新健康检查 |
| E2E-10 | 空白机安装 | 在空白 Ubuntu 以可重复的一键安装流程完成 `/setup`、迁移和首个应用上线 |
| E2E-11 | 轻量画像 | Lite 画像真实空闲运行与既有镜像发布成功；Standard 画像完成受限本机构建；记录内存、CPU、磁盘峰值且不影响 API/Worker 健康 |
| E2E-12 | 中文主路径 | 从资源创建、来源配置、部署失败、测试门禁到回滚，用户可只依赖中文界面与中文操作指引完成闭环 |

## 4. 阶段退出标准

- **P0**：产品、技术和本验收规范无“手动触发唯一”、单进程 Worker 或 Edition 伪实现的冲突；README 仅陈述已验证状态。
- **P1**：干净 Self-Host 安装执行迁移成功，镜像提供 SPA 与 `/setup`；GHCR 发布制品能拉取运行。E2E-10 是阻断项。
- **P2**：E2E-01 通过，含重放 webhook 去重和 CI 失败拦截。
- **P3**：独立 Worker/Build Worker 在重启与超时中满足 E2E-04；部署引用 digest 固定制品。
- **P4**：E2E-02、E2E-03、E2E-05、E2E-07 全部通过。
- **P5**：真实测试、Issue、复测和 Release 门禁在一条部署中可追溯，阻断规则生效。
- **P6**：Agent、多个 BYOS 节点及 Cloud 多租户分别有隔离与授权 E2E；未通过前 Cloud 继续标“未实现”。
- **P7**：E2E-01 至 E2E-12 全通过，并完成安全审计、故障恢复演练和发布签核。

## 5. 当前基线审计（2026-07-22）

本次重构已完成可审查的代码基础：Self-Host Compose 分为 `postgres → migrate → api + worker`，生产镜像构建 Web SPA，API 不再挂 Docker Socket；GitHub webhook 具备 HMAC 验签、delivery 去重、分支策略与可选 GitHub App CI 门禁；SSH 路径要求非 root 密钥和固定 Host Key，并为失败部署安排对上一成功目录的回切；GHCR 构建/Provenance/SBOM 流水线与空 PostgreSQL 迁移 CI 已加入。

但这**不是验收通过**：Docker daemon 当前不可用，尚未完成实际镜像构建或 Self-Host 启动；没有 GitHub App 安装、Registry、SSH 节点、域名、Let's Encrypt 或外部数据库的真实证据。BuildKit/OCI digest 构建与远端按 digest 拉取已有代码路径，但尚无 Registry 实证；Traefik/Caddy 流量切换、Agent、多节点、Cloud 多租户和完整项目级 RBAC 仍未实现；E2E-01 至 E2E-10 全部保持未验收。
